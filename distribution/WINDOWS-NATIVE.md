# Windows native manager — app-only build

Этот архив содержит заново собранные **наши Donut, proxy-worker и Xray**, matching source и отдельный каталог данных. Это **не новый CBrowser155/156**: browser engine в app-only архив не включён. Старые проверенные Windows EXE/ZIP с нашим CBrowser1.33/technical146 сохранены отдельно, без перезаписи.

## Почему свежий движок пока отдельно

На проверке2026-11-01 последний GitHub Stable-tag upstream —155.0.8059.39.2-pro; текущая документация также предлагает preview156. Эти версии используют официальный license key даже для бесплатного режима. Старый146 — отдельная версия, не её обновление. Публичный GitHub содержит wrapper, а не C++исходники ядра.

Для проверки нового ядра нужен свежий дистрибутив/исходники от разработчика либо официальный доступ, настроенный локально. Ключ нельзя включать в ZIP, Git, Actions artifacts, чат, argv или логи. Подтверждённое право владельца на свой форк сохраняется; отсутствие файла/ключа — техническая недостающая зависимость, не новое требование доказывать это право.

## Что уже наше

Нативный менеджер, профиль/seed/lifecycle, сеть/proxy/GeoIP/timezone/locale/geolocation/WebRTC, MCP/REST, агентские инструкции. В текущей сборке исправлены standalone-CBrowser/Wayfern terms boundary и race публикации готовности proxy-worker. Внутренние закрытые C++патчи предыдущего engine не объявляются автоматически перенесёнными на другой binary.

## Открытие менеджера

1. Полностью распаковать в свою writable-папку Windows x64. Нужен Microsoft Edge WebView2 runtime (обычно уже есть на Windows11).
2. Проверить внешний SHA256.json и внутренний MANIFEST.json. Запустить `Open manager.cmd` — это осознанный локальный UI-запуск. Данные и TEMP — только `state/` рядом с копией; личная установка не заменяется.
3. В этой копии нет engine: нельзя считать MCP/browser-сценарий готовым до настройки совместимого локального CBrowser и выполнения реального smoke. Не выбирать существующий личный профиль как тестовый; создать новый после настройки.
4. Секреты/входы вводит пользователь локально. Agent/client boundaries — CLIENTS.md и AGENT-GUIDE.md. NativeMCP — широкий административный каталог, не read-only sandbox.

## Воспроизводимая сборка

На Windows/MSVC с Node24, pnpm из packageManager, Rust и Python3.12+:

`python distribution/build_windows.py --work <новая-папка-на-D> --output <новая-папка-на-D>`

Ручной workflow `.github/workflows/agent-kit-windows.yml` делает то же на отдельном hosted runner. Секреты/профили владельца не передаются, external engine не скачивается и не подменяется. Это не publicRelease и не автообновление установленного Donut. Сам факт успешной компиляции/манифеста не равен проверке GUI/MCP/CBrowser; отдельные runtime-проверки указываются в отчёте.

Root146_Cl.txt оставлен как историческое техническое соответствие CBrowser1.33; его наличие не утверждает, что здесь есть146 или что155 был собран из исходников. Старые полноценные1.33 EXE/ZIP остаются в прежнем release-каталоге.
